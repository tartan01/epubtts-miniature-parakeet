结论：没有一个默认后端同时满足「中文整本书 + 2026 级自然度 + 许可证干净可商用」；没有一个把一本书建模成可持久化、可中断、可查询、可取消、可幂等重入的 Job；没有一个把 CLI 与 MCP 统一到同一份 handler。这就是本框架的立足点：TTS 引擎只是可插拔 Provider，护城河在工程化控制面与可复现流水线。

3 · 数据流水线：一本书怎么变成分类好的音频

S1 INGEST
校验与元数据container.xml / OPF / spine；encryption.xml 只含字体混淆≠DRM；输出 book.json
S2 SPLIT
按目录切章nav.xhtml / NCX + TOC anchor 二次切分；分类 frontmatter / body / appendix / footnote
S3 NORMALIZE
文本前端语义块清洗 → WeTextProcessing TN → 专名发音词典 → 语义分句 20–80 字
S4 SYNTH
本地 GPU 合成锁定 profile_hash；全书只算一次音色；段级内容寻址缓存；逐段 WAV
S5 VERIFY
ASR 回验转写与 text_norm 比对 CER；>5% 换 seed 重生成；静音/时长/削波抽检
S6 MASTER
母带与导出两遍 loudnorm(-16 LUFS) → 每章独立 m4a → 整本 M4B + CHAPTER 标记 + manifest

三个最容易被低估的工程点

  • 不要用 EbookLib 做语义切分：它只做对象级读写，且是 AGPL-3.0。自写 zipfile + lxml 轻量解析器（约 300–500 行）换零许可风险与完全可控的 anchor 切分。
  • 保留两份文本：text_raw 与 text_norm 附字符偏移映射 —— "念错一个字 → 定位原文 → 只重生成该段" 才能闭环。
  • 音色一致性：全书只计算一次 speaker prompt 生成 profile_hash，所有段落复用；禁止逐段重新克隆 / 随机 seed。固定全局风格向量 + 短句化可抑制 500 字后的语调漂移。

5 · 产物契约：「分类整理好」的落地定义

workspace/<book-id>/                     # book-id = sha256(epub)[:12]
├── manifest.json                       # 全书总账：元数据 + 每章状态 + profile_hash + config_hash
├── book.json / chapters.json / segments.json
├── pronunciation.toml                  # 可编辑：专名 → 拼音/读法（进 profile_hash）
├── audio/
│   ├── chapters/
│   │   ├── 0001_序章/            audio.m4a  chapter.json
│   │   ├── 0002_第一章_xxx/      audio.m4a  chapter.json
│   │   └── ...
│   └── book.m4b                        # 整书：CHAPTER 标记 + 封面 + 作者（media_type=2）
├── book.ffmetadata / cover.jpg
├── checkpoints/                        # 章节级断点 + profile.json
├── logs/job.ndjson                     # 单调递增 cursor 事件流
└── qc/report.json                      # ASR 回验 / 响度 / 静音抽检

manifest 每章记录：id / index / title / kind / audio 路径 / sha256 / 秒数 / status / qc.cer / qc.lufs / source.href+anchor。这就是给大模型读的地图。

6 · 控制面契约

CLI · 统一 JSON envelope

stdout 只出数据，stderr 只出日志；非 TTY 强制 json；CMD 与 PowerShell 5.1 各给一套示例。

类别命令
自省--capabilities --schema doctor version
只读探测book inspect book chapters book plan --dry-run
引擎engine list engine test
任务job start status list logs cancel resume artifacts
导出/服务book export serve mcp serve

退出码：0 成功（异步为 queued）· 2 参数 · 3 not found · 5 冲突/非法转移 · 69|75 可重试 · 130 取消

MCP · 薄适配，SLA ≤ 2s

任何 >2s 的操作只做提交/查询/取消，立即返回 job_id。顶层 structuredContent 一律 object。

tool要点
capabilities plan自描述 + 可验证 dry-run
job_startjob_id + resources{} + poll_interval_ms
job_status job_logs单调 progress / NDJSON cursor
job_cancel job_resume协作式 / 断点续传
job_artifacts返回 resource_link，不嵌二进制
book_inspect doctor只读探测与自检

Resources：job:///{id}/manifest.json|log.ndjson|artifacts/*；Prompts：operate_playbook 把标准编排顺序直接喂给宿主模型。

MCP 2026 现状：最新修订 2026-07-28 移除 initialize/session、新增 server/discover、日志改走 stderr、移除 SSE 可恢复性（断流即丢 in-flight 请求）、Tasks 降为 Beta 扩展。实现要双版本兼容（2026-07-28 + 2025-11-25）；显式 job_* tools 才是唯一稳定面，Tasks 只做可选增强。Windows stdio 三大坑：stdout 用 buffer.write(utf-8 bytes)+flush（chcp 65001 救不了管道，cp936 截帧会造成"工具列表假缓存"）、日志全走 stderr、env 注入 PYTHONUTF8=1。

任务状态机

job_start ─► queued ─► running ◄──► paused
                │         │  ▲          │
       cancel ───┤         │  │ resume   ├─► cancel_requested ─► cancelled (终态)
                │         ▼  │          │
                │    input_required ────┘
                │         ├──► completed (终态，result.json 原子落盘)
                │         └──► failed (终态；retryable + checkpoint 经 job_resume 回 running)
                └─────────────────────► cancelled

revision CAS 乐观锁防双启动；progress.monotonic 全局单调递增、换 phase 不归零；章节级为主控粒度，句子级只进 NDJSON 日志；幂等键同参返回逐字节一致输出，异参退出码 5。

7 · 质量保障与 Windows 部署要点

质量闭环

  • ASR 回验：合成 → faster-whisper 转写 → ITN 归一化比对 CER；>5% 自动换 seed / 提高 repetition_penalty 重生成
  • 母带：ffmpeg 两遍 loudnorm（-16 LUFS、linear=true、显式 -ar 48000）；单遍会 riding gain 导致章首爆音
  • 拼接：12ms fade + 段落停顿 + 章末静音
  • 缓存：段 key = sha256(text_norm + profile_hash + engine_version + params)，重跑不重复烧 GPU

Windows 必写进手册的坑

  • TORCH_COMPILE_DISABLE=1：<16GB 卡首次合成触发 Triton 内核编译，出声前就 OOM
  • CUDA ≥12.8（Blackwell 50 系必须）；锁 triton-windows 3.4.x；不用 DeepSpeed
  • CosyVoice3 锁 Python 3.10，openai-whisper 单独装否则重拉 PyTorch
  • activeCodePage=UTF-8 应用清单 + longPathAware；中文路径双引号
  • PowerShell 5.1 无 &&；重定向默认 UTF-16LE

9 · 需要你拍板的 6 个决策点

D1 引擎　默认按本报告选 CosyVoice3？还是先只做 Kokoro 校样链路验证控制面、引擎后置？
D2 音色来源　预设音色 / 用户提供 10–30s 参考音频克隆 / 纯文字 VoiceDesign？
D3 交付形态　仅分章文件，还是同时强制出整本 M4B？
D4 ASR 回验　全量 / 每章抽检 / 默认关闭（速度优先）？
D5 Worker 形态　常驻 daemon（推荐）还是 CLI 进程内跑（简单但断连即停）？
D6 分发　portable zip + uv（快）还是 PyInstaller 单 exe（免环境）？
