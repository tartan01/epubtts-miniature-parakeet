# 2026-11-24 夜 · v0.6 阅读器

## 用户这一轮要什么

> 「这是一个版本，然后我们再在这个基础上修改一个另一个版本把它叫做阅读器，
> 就是边读它同时在生成后面的章节，我们边读文字，它边朗读。……
> 我们在看的时候，他同时在生成语音。然后这样他通过阅读器我们可以边看……
> 支持 epub 格式」

拆成三条：
1. 以**阅读器**形态查看 EPUB 正文；
2. 看文字的时候**同时朗读当前段落**；
3. 后台**提前生成后面章节**的语音，因为「人看肯定没有机器合成快」。

## 判断与决策

- **不新建第三条代码线**：阅读器 = `mini/` 单 exe 的 `reader` 模式（ADR-027）。
  理由：v0.4 刚把结构理清，再开一条线会重复三份 EPUB 解析 / SAPI / 配置。
- **段落级同步**（ADR-028）：整章合成会让第一句等太久；字级要 `SpeakProgress` 时间戳 + `waveOut`
  定位，在 PowerShell 封装下不可靠。段落级既贴合阅读节奏，又让预取窗口天然成立。
- **跨章预取窗口**（ADR-029）：`window_end = max(cursor + 6, 下一章首段 + 2)`。
  只在章内预取，读完本章末尾会卡住等下一章。
- **播放动态加载 winmm**（ADR-030）：不给 `rust-lld` 自包含链接增加 `winmm.lib` 依赖。

## 实现

新增 `mini/src/reader.rs`（约 900 行）：

- `ReaderState`：`book / segs / cursor / playing / follow / prefetch / gen / chapter / cache_dir`
- `generator_loop`：窗口内 `Pending` 段依次合成；生成前记 `gen`，完成时代际不符就只写缓存不改状态
- `player_loop`：等当前段 `Ready` → `play_wav_sync` 同步播完 → `cursor++`
- Win32 三栏窗口：章节 ListBox / 正文只读 EDIT（`EM_SETSEL` 高亮 + `EM_SCROLLCARET` 跟随）/
  段落导航 ListBox（`·` 已备 / `⋯` 生成中 / `○` 未生成 / `!` 失败）
- 底部：上一段 / 播放暂停 / 下一段 / 语速 ± / 重合成本段 / 跟随开关 / 整本导出 / 预取深度
- `WM_DROPFILES` 拖入 `.epub` 换书；`last.txt` 记住上次的书（绝对路径）

## 这一轮踩到的坑

1. **E0170**：`match self { Pending => … }` 把变体名当成了绑定 → 全部写 `SegState::Pending`。
2. **E0502**：`s.log(if s.playing {…})` 同时可变+不可变借用 → 先算出 `&str` 再 `s.log(msg)`。
   生成线程里 `s.log(format!(… s.segs[..] …))` 同理，先算数字。
3. **只读 EDIT 失焦不显示选中** → `SetFocus(edit_text)`（缺陷 #30）。
4. **`NullReporter` 往 stdout 打印** → MCP/CLI 协议通道被污染（缺陷 #27），顺手修掉。
5. **缓存键没规范化** → 同一本书不同路径写法重复合成（缺陷 #28）。
6. **缓存目录原本放在安装目录里** → 卸载会删用户数据，设计阶段改到 `ReaderCache`（缺陷 #29）。
7. **`last.txt` 存相对路径** → 快捷方式启动（cwd=安装目录）恢复失败，改存绝对路径并去掉 `\\?\` 前缀。
8. **`Add-Type` 被宿主安全策略拦截** → 截图改用 Python `PIL.ImageGrab`。
