## 2. 先做的判断：中文乱码到底是不是 bug

上一轮记录「委托 Full 时事件流出现 `鏁存湰涔﹀凡瀹屾垚`」。本轮实测定性：

- 把 Full CLI 的 stdout 重定向到文件，`整本书已完成` 的 UTF-8 字节偏移 14150 处命中，
  GBK 字节未命中 → **Full 输出是干净 UTF-8**；
- 把 Mini 的 stdout/stderr 也重定向到文件按 UTF-8 解码，全部中文正确；
- 在 PowerShell 5.1 里直接 `& $mini run ...` 复现乱码；设
  `[Console]::OutputEncoding = [Text.Encoding]::UTF8` 后立刻正常。

**结论：宿主用 GBK(936) 解码子进程 stderr 的显示问题，不是程序缺陷**（缺陷 #25 / ADR-026）。
因此**不改程序输出编码**（会破坏 CLI/MCP 的 JSON envelope 契约），改为在
`help` 与便携包 `使用说明.txt` 给出 `chcp 65001` 指引。

## 3. 真正修掉的三个缺陷（`mini/src/audio.rs::delegate_full`）

| 问题 | 原状 | 修复后 |
|---|---|---|
| 日志 | 把 Full 的整行 NDJSON 原样 `rp.log` | 解析 JSON，只输出 `[stage] message`；`segment_done` 驱动 `rp.progress()`（GUI 进度条会动）；上限 200 行 |
| engine 标签 | 硬编码 `sherpa-via-Full`，即使用 `--engine mock` | 从 Full 的 `manifest.json` 读 `engine.name`，动态生成 `mock-via-Full` / `sherpa-via-Full` |
| 统计 | `chapters/paragraphs/seconds=0`，`wav_bytes=57344`（只数到 `bookctl.db`） | 读 Full manifest 的 `totals.chapters / totals.audio_seconds / chapters[]` + 事件流 `normalize_done.segments`；`dir_size_recursive()` 递归统计 |

新增辅助函数：`dir_size_recursive()` / `find_full_manifest()` / `full_chapter_rows()`。
修复后实测：`chapters=3 / paragraphs=14 / seconds=10.1 / engine=mock-via-Full /
wav_bytes=681002`，Mini 的 `manifest.json` 含 3 条真实章节（含标题/秒数/音频路径），
`chapters.txt` 三行齐全。

## 4. 顺带修掉的可用性缺陷（#26）

`Uninstall-Mini.exe` 是安装器 stub 的头部副本（故意不带 overlay payload）。原来只有显式
`/UNINSTALL` 才进卸载分支，**无参数双击**会掉进安装路径并报「这不是完整的安装包」。
`mini/setup/main.rs::main()` 增加按文件名前缀 `Uninstall-` 判定，两条路都覆盖。

> 非交互宿主里双击卸载会弹「卸载完成」MessageBox 并阻塞 → 自动化验收统一用 `/UNINSTALL /S`。
