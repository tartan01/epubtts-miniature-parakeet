## 1. 触发本轮的用户原话

用户在批准 A 路线后，一次性给出了 Mini 产品线的完整需求（原文要点）：

> 「A（推荐）：新增独立 `mini/` 产品线 —— Rust + Windows 自带语音（SAPI/WinRT），零模型、
> 单 exe 约 5–10 MB、无 .NET 无 Python，保留 CLI/MCP 契约，与现有 .NET 主线并存。
> 很好，那你就继续做一个轻量化的版本吧。
> 关于 Mini 产品线，核心需求是**保留按钮，但改变用户体验**。目前用户想要本地使用时，
> 需要自己去网上找很多镜像一个一个试；新版本要求软件内置自动适配功能，
> 自动让用户选择一个地址安装（安装到 C 盘、D 盘、E 盘等任何盘都可以），
> 用于存放那些重量级的 TTS 模型文件。本机软件只需作为一个轻量级的入口，具备以下功能：
> 1. 运行配置：能够选择显卡、CPU 等运行环境并导入配置。
> 2. 核心功能：自动调用 TTS 模型来进行语音朗读生成。
> 3. 下载管理：(a) 内置多个下载源。(b) 异常提示与进度显示：若网络连接不通或其中一个源下载失败，
>    需及时提示用户，并显示下载进度。(c) 资源定位：提供一个按钮，让用户能够直接打开模型文件
>    所在的资源地址。(d) 版本封装与安装：做轻量化的更改，同时把之前的重量级版本也保存好。
>    这两个版本（重量级和迷你版）都需要全部封装成 `.exe` 文件，支持用户一键安装。
>    安装后的表现需和常规 Windows 软件一样，会在用户目录下生成文件夹，并写入注册表等信息。
> 我等一下会拿另一台电脑传过去测试。好，你现在继续开始修改，进行这个新项目的更改吧。」

## 3. 本轮关键技术决策

| 决策 | 结论 | 记录位置 |
|---|---|---|
| 路线 | A：独立 `mini/` 产品线，Rust + Win32，与 .NET 主线并存 | ADR-021 |
| 工具链 | `stable-x86_64-pc-windows-gnu` + `rust-lld` + `link-self-contained`（免 MSVC/SDK） | ADR-021、`.cargo/config.toml` |
| 语音 | Mini 自身不加载权重；检测到 Full 委托真 TTS，否则系统 SAPI 兜底，再否则明确标注占位音 | ADR-022 |
| 模型存放 | 程序装 `%LOCALAPPDATA%`，模型由用户选盘（C/D/E…），路径写 `config.json` | ADR-023 |
| 下载 | 内置 8 源 + 自动测速 + 失败自动切源 + 字节/速度/ETA/百分比进度 + 打开模型目录按钮 | ADR-024 |
| 封装 | 自研 overlay 自解压 setup.exe；Mini/Full 共用 stub；HKCU 免管理员；两阶段卸载 | ADR-025 |
| 委托回填 | 解析 Full 的 NDJSON + 读 Full manifest 回填真实统计；engine 标签动态生成 | ADR-026 |
| 中文乱码 | **不改程序输出编码**，`help`/使用说明给 `chcp 65001` 指引 | ADR-026、缺陷 #25 |

## 4. 用户反馈里反复强调的行为约束

- 「保留按钮，但改变用户体验」→ GUI 不删控件，改的是「不用手工找镜像、不用选路径」。
- 「不要自己去找镜像一个一个试」→ 自动测速选源 + 失败自动切下一个源。
- 「安装到 C/D/E 任意盘」→ 盘符枚举 + 剩余空间显示 + `model_root_for(letter)`。
- 「两个版本都一键安装、写注册表」→ 两个 setup.exe 都写 HKCU、用户目录、快捷方式、`.epub` 关联。
- 「我等一下会拿另一台电脑传过去测试」→ 交付必须给出可拷贝的绝对路径与逐步验收清单。
- 「先在沙箱模拟一下运行测试」→ 每个改动都实测（编译 / CLI / MCP / 安装 / 卸载 / 委托生成）。
